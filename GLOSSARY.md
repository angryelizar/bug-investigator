# Bug Investigator

Агент-помощник разработчика: принимает сообщение об ошибке, находит проблемный код в репозитории и предлагает Pull Request с исправлением.

## Вход и разбор

**Bug Report**:
Описание неправильного поведения программы, с которого начинается работа агента: текст, вставленный в чат, или содержимое issue. Стек-трейс в нём желателен, но не обязателен.
_Avoid_: ошибка, тикет, инцидент, задача

**Target Repository**:
Репозиторий, в котором агент ищет и исправляет код; задаётся конфигурацией стенда.
_Avoid_: проект, кодовая база

**Investigation**:
Один прогон агента от Bug Report до итогового результата. Одному Bug Report соответствует одна Investigation.
_Avoid_: сессия, запуск, задача

**Analysis**:
Первый этап Investigation, на котором агент решает, что представляет собой Bug Report, и выносит Verdict.
_Avoid_: triage, формализация, проверка задачи

**Baseline**:
Результат сборки с тестами исходного кода Target Repository до каких-либо изменений агента.
_Avoid_: исходная сборка, health check

**Verdict**:
Итог Analysis: «Подтверждено» (проблемное место в коде найдено), «Не баг» (код работает как задумано), «Недостаточно данных» или «Заблокировано» (Baseline красный из-за проблемы, не связанной с Bug Report).
_Avoid_: статус, problemVerified

## Исправление

**Plan**:
Описание того, как агент собирается исправить подтверждённый баг: где причина, какую Reproduction написать и что изменить в коде.
_Avoid_: план реализации, стратегия

**Fix**:
Предложенное агентом изменение кода Target Repository, ещё не оформленное как Pull Request.
_Avoid_: патч, решение, реализация

**Reproduction**:
Тест, который падает из-за бага, описанного в Bug Report, и проходит после Fix.
_Avoid_: регрессионный тест, тест на баг, псевдотест

**Reproduced Fix**:
Fix, у которого есть Reproduction; только про него можно утверждать, что баг исправлен.
_Avoid_: проверенный, подтверждённый, протестированный

**Unreproduced Fix**:
Fix без Reproduction: известно лишь, что он собирается и не ломает существующие тесты.
_Avoid_: непроверенный, слабый

**Verification**:
Проверка Fix до того, как его увидит человек: сборка с тестами в песочнице и самокритика агента.
_Avoid_: ревью, тестирование, executor

## Решение человека и результат

**Approval**:
Решение человека в точке паузы: одобрить, отклонить или вернуть на доработку с комментарием. Бывает Plan Approval, Fix Approval и подтверждение вердикта «Не баг».
_Avoid_: подтверждение, ревью, isPlanApproved

**Fix PR**:
Pull Request в Target Repository, созданный из Fix после Fix Approval. Агент его не мержит.
_Avoid_: PR-фикс, merge request
