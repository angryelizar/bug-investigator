# Жёсткий конвейер агентов вместо свободного оркестратора

Порядок этапов Investigation задан графом LangGraph: Analyst → Planner → Coder → Executor → Critic, затем Approval и публикация Fix PR. Orchestrator — это условные переходы в коде, а не LLM-агент. Модель свободна только внутри этапов Analyst, Planner и Coder (цикл ReAct с инструментами). Executor и публикация выполняются без модели. Так решили потому, что проект работает на слабых бесплатных моделях с жёстким лимитом токенов. Свободный агент или LLM-супервизор тратит запросы на маршрутизацию и может пропустить Verification или Approval, а конвейер физически не даёт этого сделать.

## Consequences

- Git, Docker и GitHub вызывает граф, а не модель; модели доступны только поиск, чтение и запись файлов.
- Между этапами передаются только короткие итоги, а не переписка модели с инструментами, — иначе запрос не укладывается в лимит токенов.
- Перепланирование — это петля Critic → Planner с лимитом попыток, а не решение модели о следующем шаге.
